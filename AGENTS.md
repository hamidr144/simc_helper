# Repository workflow

Follow **WORKFLOW.md** at the repo root. Summary: cut a `feature/<kanban-id>-<slug>` branch from `dev` (the default branch), test on the dev system (port 8001), open a PR via `gh pr create --base dev` — CI runs checks on every PR to `dev`/`prod` (no checks ≠ passing checks). Review happens on the PR via `gh pr review` (first line `VERDICT: APPROVE`/`VERDICT: REQUEST-CHANGES` — shared identity, GitHub rejects self-approval). **The leader merges via `gh pr merge --merge` and tags the merge commit; the author never merges their own work, workers never merge.** Automation identity: the team's GitHub App bot (shared fine-grained PAT as stopgap fallback). `prod` gets its PR only from the leader at approved, explicitly shipped milestones. Never commit, merge or push directly to `dev` or `prod` — the `pr-only-dev-prod` ruleset rejects it server-side — and never touch branch protection, rulesets, or the default-branch setting: the user edits those in the browser.
