# Realm List (`realms.json`)

The character-setup realm dropdown is populated from a static snapshot of the WoW retail realm list at `src/web/static/realms.json`, regenerated by `scripts/refresh_realms.py`. This document is the maintainer runbook for that file.

> [!IMPORTANT]
> `realms.json` is a **snapshot, not a live feed**. Always describe it as "up to date as of the `generated_at` date" — never as live or current.

---

## 1. What the file is

`realms.json` is a static snapshot of the retail realm list (EU + US) scraped from `https://everythingwow.com/realms`. The Blizzard Game Data API is dead as of 2026, so this third-party mirror is the source of record.

The **grouped schema below is authoritative** per the amended ruling on motion `t_48640f20` (comment 424 on `t_3b46a74b`); the earlier flat-schema ruling is withdrawn. Do not hand-edit the file and do not accept a regenerated file in any other shape.

Top-level keys:

| Key | Meaning |
| --- | --- |
| `generated_at` | UTC timestamp of this regeneration — the date the list is up to date as of |
| `source` | URL (or `file:` path for offline runs) the snapshot was built from |
| `source_crawled_at` | The source site's own newest-crawl stamp, if present |
| `counts` | Per-region deduped realm counts, e.g. `{"eu": 267, "us": 246}` |
| `realms` | Object with exactly two keys, `eu` and `us`, each a list of realm records sorted by name |

Each realm record carries exactly the fields agreed in `t_3b46a74b`:

```json
{
  "region": "eu",
  "id": 577,
  "slug": "aegwynn",
  "name": "Aegwynn",
  "type": "NORMAL",
  "timezone": "Europe/Paris",
  "population": "LOW"
}
```

Slugs are taken verbatim from the source — they are the authoritative Armory slugs (lowercase, apostrophes stripped, accents preserved, e.g. `pozzo-delleternità`). Realms such as Kel'thuzad exist in **both** regions with different ids, so region is part of a realm's identity everywhere; entries are never deduped by name.

## 2. How to regenerate

Run the script **manually**, from the project root:

```bash
.venv/bin/python scripts/refresh_realms.py
```

Offline/hermetic run against a saved copy of the source page (used by tests):

```bash
.venv/bin/python scripts/refresh_realms.py --input saved_page.html -o /tmp/realms.json
```

Rules:

* **Never wire it into cron, CI, or docker compose.** Regeneration is a deliberate, reviewed act; every run bumps `generated_at` and rewrites the whole file, so it must land in a normal commit with a reviewable diff.
* **A browser User-Agent is mandatory.** The source site has been observed serving 0 bytes to bare `curl`. The script sends a browser UA automatically — do not replace the fetch with a plain `curl`/`wget` pipeline.
* **The script is fail-loud.** A short response, zero parsed records, a blob/anchor cross-check mismatch (schema drift), a malformed record, or a per-region count outside the 150–400 sanity band all exit 1 with a clear message.
* **The write is atomic.** Output goes to a temp file and is renamed over the target only after every check passes, so a failed run leaves the previous `realms.json` untouched.
* Output is deterministically sorted (casefolded name, then id) so regeneration diffs stay reviewable.

After a successful run, review the diff (expect realm-set changes plus `generated_at`/`counts`) and commit it like any other change.

---

## 3. When to regenerate

There is no schedule. Regenerate when:

1. **An expansion pre-patch lands** — realm merges/additions cluster around these.
2. **Blizzard announces a new realm** and it is missing from the list.
3. **A user reports a missing realm** in the dropdown.

The source site itself is crawled daily, so a manual re-run after any of these triggers is enough; do not re-run just because `generated_at` looks old.

---

## 4. How the dropdown consumes it

On page load, `src/web/static/app.js` fetches `/static/realms.json` and, on success:

* builds one `<optgroup>` per region (EU/US) in the realm `<select>`;
* keys each option as `region/slug` (region-qualified because names collide across regions) and shows `type · population · timezone` in the option tooltip;
* enables and unhides the select, and syncs the region selector when a realm is picked.

Payload rules in `buildArmoryPayload`: a pasted Armory link wins over everything; a realm **typed** into the input (`Name-Realm`, `Name, Realm`) wins over the dropdown pick; the dropdown only supplies the realm for a bare character name.

**Graceful fallback:** if `realms.json` is missing, unreadable, or has an unexpected shape, the fetch/populate step logs a console warning and the select stays hidden and disabled (its initial markup state). The user sees nothing broken — free-text `Name-Realm` typing works exactly as before. A stale snapshot therefore degrades to "some realms missing from the list", never to a broken import.

## 5. Troubleshooting

| Symptom | Meaning / action |
| --- | --- |
| `no realm records matched` | The source page's SSR blob layout changed (key reorder/renames). Inspect the parser in `scripts/refresh_realms.py` before shipping; do not hand-patch the JSON. |
| `blob/anchor mismatch` | The parsed records disagree with the page's `/realms/retail/(eu|us)/{slug}` href anchors — schema drift. Same action as above. |
| `count ... outside sanity band 150..400` | Either a truncated scrape or a genuine large-scale realm-set change. Verify against the source page manually before adjusting the band. |
| Dropdown absent in the UI | `realms.json` failed to load — check the browser console warning and that the file is served at `/static/realms.json`. |
